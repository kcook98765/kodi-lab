# Phase 11 MCP transports and security

Kodi Lab's primary MCP authority is modern Streamable HTTP POST `/mcp`, exact
protocol `2026-07-28`. Canonical stdio is not a second server implementation.
Installed command `kodi-lab-mcp-stdio` forwards bounded stdio requests to the
same authenticated loopback HTTP route, so both transports use identical
durable client identity, credential lifecycle, preset permissions, exact target
grants, target policy, tool registry, capability/state checks, tool schemas,
ordering, and bounded error mapping.

## Generic stdio client configuration

Configure:

- command: `kodi-lab-mcp-stdio`;
- environment: `KODI_LAB_MCP_TOKEN=<token shown once by Web administration>`;
- arguments: none;
- target choice: explicit `target_id` in every target-scoped tool call.

Do not put the token in argv, a URL query, an MCP protocol payload, or a
plaintext client file generated by Kodi Lab. The adapter reads no token from
stdin. Environment variables are not perfect secret storage: sufficiently
privileged same-user or root processes may inspect them. This design addresses
the intended local/LAN trust boundary, not hostile same-account isolation, and
does not make plaintext config storage safer.

The default URL is `http://127.0.0.1:8100/mcp`. For development/test listeners,
`KODI_LAB_MCP_URL` may select another port on exact `127.0.0.1` or `localhost`,
but the scheme remains `http`, the path remains `/mcp`, and userinfo, query,
fragment, redirects, and remote hosts are rejected. The adapter is therefore
not a generic MCP forward proxy.

## Authority and lifetime

Every stdio request carries `Authorization: Bearer <token>` to `/mcp`. The
adapter does not inspect token authority, construct Kodi Lab repositories or
services, or cache a verifier, principal, grant, preset, target policy,
capability, state, or tool list. Revoke, disable, preset changes, grant removal,
and policy changes therefore apply on the next request.

There is no initialize/initialized exchange, legacy fallback,
`Mcp-Session-Id`, application transport session, selected/default target, GET
stream, daemonization, or durable adapter state. Stdin EOF cancels active work
and ends the process. Input frames are bounded to 64 KiB before JSON parsing;
four workers and an eight-item backpressured queue bound local work while the
HTTP server retains authoritative admission.

The adapter executable alone grants no authority. A process must possess a
valid bearer, and that bearer grants only its durable MCP client's current
intersection of permission, exact grant, target policy, tool metadata, target
class, capability, and state. Stdio is a transport, not an internal,
development, or production target trust class.

Kodi Lab sends no spoofable transport-origin header. Server audit observes the
HTTP authority path and does not claim that a request came through stdio;
transport classification never changes permission in this slice. Stable
adapter errors omit bearer values, tracebacks, HTTP library detail, and endpoint
internals.

Production tools remain exactly `target_list` and `target_status`. Legacy
`2025-11-25`, add-on inventory, screenshots, remote control, raw JSON-RPC,
lifecycle, snapshots, logs, diagnostics, external targets, and Phase 12
workflows remain excluded.
